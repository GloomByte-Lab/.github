# Contributing

Thanks for taking the time to contribute to a GloomByte Labs project.

## Before you start

Search existing issues and pull requests before opening a new one. For a large
feature, behavior change, or architectural change, open an issue or discussion
first. This gives maintainers and contributors a chance to agree on scope.

Do not use a public issue to report a security vulnerability. Follow the
[security policy](SECURITY.md) instead.

## Make a change

1. Fork the repository and create a branch from its default branch.
2. Keep the change focused. Separate unrelated work into another pull request.
3. Follow the setup, formatting, and test instructions in the project README.
4. Add or update tests when behavior changes.
5. Update documentation when users or contributors need to know about the
   change.
6. Open a pull request and complete its checklist.

Small documentation corrections may go directly to a pull request. Link code
changes to an issue when one exists.

## Pull request review

Maintainers review pull requests for correctness, security, tests,
documentation, compatibility, and fit with the project's scope. Address review
comments with new commits so the discussion remains easy to follow.

A maintainer may ask to split a large pull request or close work that does not
fit the project. That decision is about scope, not the value of the idea.

## Licensing

By submitting a contribution, you agree that it may be distributed under the
license of the repository unless the maintainers have documented a different
arrangement.

All contributors must follow the [code of conduct](CODE_OF_CONDUCT.md).
