# Governance

GloomByte Labs projects use maintainer-led, public development.

## Contributors

Anyone who reports problems, improves documentation, reviews changes, writes
code, or helps other users is a contributor.

## Maintainers

Maintainers review issues and pull requests, set release scope, protect project
security, and enforce community standards. They are expected to explain
decisions in public when privacy and security allow it.

Regular contributors may be invited to become maintainers after showing sound
technical judgment, constructive collaboration, and sustained participation.
Existing maintainers make that decision by consensus.

## Decisions

Normal decisions happen in issues, discussions, and pull requests. Maintainers
seek consensus for changes that affect public behavior or project direction.
When consensus is not possible, the project lead makes the final decision and
records the reasoning publicly.

## Changes to governance

Governance changes use the same pull request process as code changes and need
approval from the project lead.
